### Шаг 3: Добавьте движение вниз

Падение — это не один рывок, а много крошечных сдвигов подряд. Значит, работа для `Update()`, он уже знаком по прошлым модулям.

Замените пустой `Update()` на такой:

```csharp
// Вызывается каждый кадр
void Update()
{
    transform.position += Vector3.down * speed * Time.deltaTime;
}
```

`Vector3.down` — направление «вниз», то есть `(0, -1, 0)`. Всё остальное здесь ровно такое же, как у пули из первого урока, только направление противоположное.

Сохраните файл и нажмите `Play`: астероид должен медленно уехать вниз и скрыться за краем экрана.

```check
rules:
  - filename: "AsteroidMover.cs"
  - contains: "void Update()"
  - contains: "transform.position += Vector3.down * speed * Time.deltaTime"
```

### Шаг 4: Уберите астероид, который улетел за экран

Астероид скрылся из виду — но он всё ещё существует. Он летит вниз вечно, тратит память и время процессора, и таких «невидимок» за минуту игры наберутся десятки.

Пуля решала эту проблему таймером. Астероиду таймер не подходит: он может лететь долго, если игрок не успел его сбить. Значит, проверять надо не время, а **позицию**.

Дополните `Update()` условием:

```csharp
void Update()
{
    transform.position += Vector3.down * speed * Time.deltaTime;

    // Астероид опустился ниже экрана - убираем его
    if (transform.position.y < destroyY)
    {
        Destroy(gameObject);
    }
}
```

> **Как работает по шагам:**
>
> 1. Сначала астероид сдвигается вниз — как и раньше.
> 2. Потом проверяется его новая высота: `transform.position.y < destroyY`.
> 3. Как только высота стала меньше `-6`, объект удаляется со сцены.
> 4. Префаб в папке `Prefabs` при этом остаётся целым — удаляется только эта копия.

```check
rules:
  - filename: "AsteroidMover.cs"
  - contains: "transform.position.y < destroyY"
  - contains: "Destroy(gameObject)"
```

### Шаг 5: Добавьте Circle Collider 2D и Rigidbody2D

Астероид должен уметь принимать попадания. Значит, ему нужен тот же набор, что мы делали для пули, — только форма другая: астероид круглый.

Правило из первого урока в силе: спрайт уже стоит, коллайдер добавляем после него. Тогда Unity сама подгонит радиус под картинку.

1. Выделите `Asteroid` в `Hierarchy`.
2. В `Inspector` нажмите `Add Component`, введите `Circle Collider 2D` и выберите его.
3. У добавленного `Circle Collider 2D` поставьте галочку **`Is Trigger`**.
4. Снова нажмите `Add Component`, введите `Rigidbody 2D` и выберите его.
5. В поле `Body Type` выберите **`Kinematic`**.

> **Почему снова `Kinematic`, а не `Dynamic`?**
>
> 1. Астероид мы двигаем сами кодом через `transform.position` — гравитация нам не нужна.
> 2. `Kinematic` как раз означает «этот объект двигаю я, физический движок его не трогает».
> 3. При `Dynamic` астероид начал бы ускоряться от гравитации и отскакивать от пуль.
> 4. `Rigidbody2D` здесь нужен ровно за тем же, зачем и пуле: без него Unity вообще не следит за пересечениями коллайдеров.

## Кто будет создавать астероиды, пока мы играем?

Можно расставить двадцать астероидов руками прямо в сцене. Но игра закончится через пять секунд, а на второй попытке всё будет ровно так же.

Значит, нужен объект, который **сам, без нас, снова и снова** создаёт астероиды, пока идёт игра. Такой объект называют **спавнером** (от английского *spawn* — «порождать»).

И у него сразу два вопроса к нам:

- **как часто** создавать;
- **где именно** создавать, чтобы астероиды не падали всё время в одну точку.

---

## Теория 1: InvokeRepeating — метод по расписанию

Обычно мы вызываем метод сами: написали `Fire();` — он выполнился. Но здесь нужен другой режим: «вызывай этот метод сам, каждые полторы секунды, пока игра идёт».

Такой таймер вы уже писали руками — в спавнере врагов Tower Defence: поле `nextSpawnTime`, проверка `if (Time.time < nextSpawnTime) return;` и строка `nextSpawnTime = Time.time + spawnInterval;`. Три строки состояния ради одной простой мысли «повторяй раз в N секунд».

В Unity для этой мысли есть готовая команда — `InvokeRepeating`:

```csharp
InvokeRepeating(имяМетода, задержкаДоПервогоВызова, интервалПовторения);
```

Три аргумента, и все три важны:

- **имя метода** — какой метод вызывать;
- **задержка** — через сколько секунд случится **первый** вызов;
- **интервал** — через сколько секунд повторять дальше.

Вызвать `InvokeRepeating` надо один раз, обычно в `Start()`. Дальше Unity сама держит расписание — нам ничего делать не нужно.

Если повтор надо остановить (например, при `Game Over`), есть парная команда:

```csharp
CancelInvoke(nameof(SpawnAsteroid));
```

Она нам понадобится в конце модуля, а пока просто запомним, что она существует.

## Пояснение (InvokeRepeating)

- Первый аргумент — имя метода, второй — через сколько секунд будет первый вызов, третий — через сколько секунд повторять.
- В шутере это самый короткий способ сделать бесконечный поток астероидов: одна строка в `Start()` вместо ручного таймера в `Update()`.

## Теория 2: nameof — имя метода без опечаток

`InvokeRepeating` ждёт имя метода **строкой**. И вот тут прячется коварная ошибка: строку компилятор не проверяет.

Напишете `"SpawnAsteriod"` вместо `"SpawnAsteroid"` — код спокойно скомпилируется, ошибок не будет, астероиды просто не появятся. Ищите потом.

Поэтому мы пользуемся `nameof` — тоже **новинкой этого модуля**:

```csharp
InvokeRepeating(nameof(SpawnAsteroid), 1f, 1.5f);
```

`nameof(SpawnAsteroid)` превращается в строку `"SpawnAsteroid"` прямо при компиляции. Разница огромная:

- если метода с таким именем нет — программа **не соберётся**, ошибка подсветится сразу;
- если вы позже переименуете метод в редакторе, `nameof` переименуется вместе с ним.

Правило простое: где нужно имя метода строкой — всегда `nameof`.

### Шаг 2: Создайте скрипт TimedSpawner и добавьте настройки

Давай подумаем, что спавнер должен знать, чтобы делать свою работу. Он должен создавать астероиды — значит, ему нужен **префаб**. Он должен ставить их в случайное место сверху — значит, нужны **границы по X** и **высота появления**. И он должен знать **когда начать** и **как часто повторять**.

Компьютер не выберет эти числа за нас, поэтому перечисляем всё явно.

1. В `Assets/Shooter/Scripts` создайте скрипт `TimedSpawner`.
2. Выделите `Spawner`, нажмите `Add Component`, введите `TimedSpawner` и выберите скрипт.
3. Откройте скрипт и добавьте настройки:

```csharp
[Header("Астероиды")]
[SerializeField] private GameObject asteroidPrefab;
[SerializeField] private float minX = -7f;
[SerializeField] private float maxX = 7f;
[SerializeField] private float spawnY = 6f;
[SerializeField] private float asteroidStartDelay = 1f;
[SerializeField] private float asteroidRate = 1.5f;
```

`minX` и `maxX` — те же границы, что у корабля: астероид должен появляться там, куда игрок может доехать. А `spawnY = 6` — выше верхнего края экрана (напомню, он на `Y = 5`), чтобы астероид «влетал» в кадр, а не возникал в нём из воздуха.

> **Что за `[Header("Астероиды")]` в первой строке?** Шесть похожих чисел подряд легко перепутать. `[Header]` — родственник знакомого `[SerializeField]`: такая же пометка в квадратных скобках, только рисует подпись над полями в инспекторе и больше ничего не делает.

### Шаг 3: Запустите таймер в Start()

Расписание заводят один раз — как будильник. Поставили в `Start()` и забыли. Поставите в `Update()` — получите 60 будильников в секунду, и астероиды пойдут стеной.

Замените пустой `Start()` на такой:

```csharp
// Запускаем расписание спавна один раз при старте
void Start()
{
    InvokeRepeating(nameof(SpawnAsteroid), asteroidStartDelay, asteroidRate);
}
```

> **Как работает по шагам:**
>
> 1. При старте сцены `Start()` выполняется один раз.
> 2. Unity ждёт `asteroidStartDelay` (1 секунду) — игрок успевает освоиться.
> 3. Затем первый раз вызывается метод `SpawnAsteroid()`.
> 4. Дальше Unity вызывает его каждые `asteroidRate` (1.5 секунды), пока объект `Spawner` активен.

Редактор сейчас подчеркнёт `SpawnAsteroid` красным — метода ещё нет. Это нормально, напишем его следующим шагом.

```check
rules:
  - filename: "TimedSpawner.cs"
  - contains: "void Start()"
  - contains: "InvokeRepeating(nameof(SpawnAsteroid), asteroidStartDelay, asteroidRate)"
```

## Пояснение (почему InvokeRepeating живёт в Start)

- Ответ `False`. `InvokeRepeating` не проверяет, заводили ли вы уже такое расписание: каждый вызов добавляет **новое**.
- В `Update()` он выполнится примерно 60 раз в секунду — и через секунду у вас будет около 60 независимых расписаний спавна.
- Отсюда и симптом «астероиды идут сплошной стеной». Лечится переносом одной строки из `Update()` в `Start()`.

## Теория 3: Random.Range — float или int?

Если все астероиды будут падать из одной точки, игрок просто отъедет в сторону и выиграет. Нужна случайность по горизонтали.

`Random.Range` вы уже применяли в Tower Defence — им выбирали высоту появления врага. Но одну его хитрость мы тогда не разбирали: у него **две разные версии**, и Unity выбирает нужную по типу аргументов:

```csharp
float randomX = Random.Range(-7f, 7f); // float: от -7 до 7, включая края
int index = Random.Range(0, 3);        // int: 0, 1 или 2 - тройка не выпадет никогда
```

> **Разница по шагам:**
>
> 1. Если оба аргумента с буквой `f` (`-7f`, `7f`) — это дробная версия, максимум **входит** в диапазон.
> 2. Если оба аргумента целые (`0`, `3`) — это целая версия, максимум **не входит**.
> 3. Целая версия сделана так специально: `Random.Range(0, array.Length)` всегда даёт корректный индекс массива.

Нам нужна позиция на экране, то есть дробное число. Значит, пишем границы с `f`.

## Пояснение (Random.Range)

- С дробными аргументами `Random.Range` возвращает `float` и включает оба края диапазона, а с целыми возвращает `int` и верхнюю границу не включает.
- В спавнере мы берём дробную версию: позиция астероида на экране почти никогда не бывает круглым числом.

## Практика 2 (продолжение): случайное место появления

### Шаг 4: Напишите метод SpawnAsteroid()

Один момент спавна — это три коротких действия: выбрать случайное место по горизонтали, собрать из него полную позицию и создать там астероид. Три действия, один метод.

Добавьте метод в класс `TimedSpawner`, после `Start()`:

```csharp
// Создаёт один астероид в случайной точке над экраном
```

## Теория 4: OnTriggerEnter2D — знакомый метод с новым именем

В модуле 3, в Dino 3D, мы уже ловили столкновения. Там это выглядело так:

```csharp
void OnTriggerEnter(Collider other)
```

Сейчас у нас 2D-игра, и физика в Unity для 2D — **отдельная система** со своими компонентами и своими методами. Поэтому имена другие:

| Dino 3D (модуль 3) | Космический шутер (2D) |
| ------------------ | ---------------------- |
| `OnTriggerEnter` | `OnTriggerEnter2D` |
| `Collider other` | `Collider2D other` |
| `BoxCollider` | `Box Collider 2D` |
| `Rigidbody` | `Rigidbody 2D` |

Логика при этом ровно та же: Unity сама вызывает метод в тот момент, когда в наш триггер что-то влетело, и передаёт внутрь объект-гость через параметр `other`.

Самая частая ошибка модуля — написать `OnTriggerEnter` без `2D`. Метод скомпилируется, ошибок не будет, но Unity его никогда не вызовет.

## Пояснение (что нужно для триггера)

- Чтобы `OnTriggerEnter2D` сработал, нужны три вещи: коллайдеры у обоих объектов, `Is Trigger` хотя бы у одного и `Rigidbody2D` хотя бы у одного.
- Без `Rigidbody2D` Unity просто не следит за этой парой — код молчит, `Console` чистая, и найти причину очень трудно. Именно поэтому мы добавили `Rigidbody2D` и пуле, и астероиду заранее.

- Поэтому первое, что проверяют при «пуля пролетает насквозь», — это две буквы в конце имени метода.

## Теория 5: как узнать, кто именно прилетел

Метод `OnTriggerEnter2D(Collider2D other)` срабатывает на **любое** касание. В `other` может оказаться пуля, корабль игрока или даже другой астероид.

Астероид должен взорваться только от пули. Значит, нужно спросить у гостя: «а есть ли у тебя компонент пули?»

```csharp
other.GetComponent<ProjectileMover>() != null
```

> **Как это читать по шагам:**
>
> 1. `other` — объект, который в нас влетел.
> 2. `GetComponent<ProjectileMover>()` ищет на нём компонент `ProjectileMover`.
> 3. Если компонент есть — вернётся ссылка на него; если нет — вернётся `null` («ничего»).
> 4. Сравнение `!= null` означает «компонент нашёлся», то есть это точно наша пуля.

Это очень удобный приём: мы не проверяем имя объекта (имена легко перепутать), а спрашиваем про его **роль** — какой скрипт на нём висит.

## Пояснение (проверка компонента)

- `GetComponent<ProjectileMover>()` возвращает компонент, если он есть на объекте, и `null`, если его нет — по этому и определяют «свой или чужой».
- В шутере это защищает от глупостей: без проверки астероид взрывался бы от касания другого астероида или от любого случайного триггера.

## Практика 3: Первое попадание

Все детали на месте. Осталось написать один метод.

### Шаг 1: Добавьте OnTriggerEnter2D в AsteroidMover

Кто должен отвечать за попадание? Пуля не знает, во что она врезалась и сколько это стоит очков. А вот астероид про себя знает всё — значит, реакцию на попадание селим в `AsteroidMover`.

Откройте `AsteroidMover.cs` и добавьте метод **внутрь класса**, после `Update()`:

```csharp
// Вызывается, когда в астероид что-то влетело
void OnTriggerEnter2D(Collider2D other)
{
    if (other.GetComponent<ProjectileMover>() != null)
    {
        Destroy(other.gameObject);
        Destroy(gameObject);
    }
}
```

> **Как работает по шагам:**
>
> 1. Unity сама вызывает метод в момент пересечения и передаёт гостя в `other`.
> 2. Условие проверяет, есть ли у гостя компонент `ProjectileMover`.
> 3. `Destroy(other.gameObject)` удаляет пулю — обратите внимание на `other`.
> 4. `Destroy(gameObject)` удаляет сам астероид — без `other` это означает «этот объект».

Разница между `other.gameObject` и `gameObject` — ровно одно слово, но объекты удаляются разные. Перепутаете — астероид будет удалять сам себя дважды, а пуля улетит дальше.

```check

  - filename: "AsteroidMover.cs"
  - contains: "void OnTriggerEnter2D(Collider2D other)"
  - contains: "other.GetComponent<ProjectileMover>() != null"
  - contains: "Destroy(other.gameObject)"
```

## Если попадание не срабатывает

Это самая частая проблема модуля. Проверяйте **не код, а настройки объектов** — почти всегда дело в них:

- у префаба `Projectile` есть `Box Collider 2D`;
- у префаба `Asteroid` есть `Circle Collider 2D`;
- хотя бы у одного из них включена галочка `Is Trigger` (у нас включена у обоих);
- хотя бы у одного есть `Rigidbody2D` (у нас есть у обоих) — **без этого триггеры в 2D молчат**;
- у обоих `Rigidbody 2D` стоит `Body Type: Kinematic`;
- скрипт `ProjectileMover` висит именно на префабе пули, а не только на объекте в сцене;
- в коде написано `OnTriggerEnter2D`, а не `OnTriggerEnter`;
- коллайдеры не крошечные: включите `Gizmos` в окне `Game` и посмотрите на зелёные контуры вокруг объектов;
- в `Console` нет красных ошибок.

Если хотя бы один пункт не выполнен, `OnTriggerEnter2D` не будет вызван вообще — и никакой ошибки вы не увидите.
