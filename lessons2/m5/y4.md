# Модуль 5, Урок 4: `GameManager` — деньги, UI и одно улучшение

**Цель урока:** добавить общий управляющий объект, который хранит деньги игрока, обновляет UI и покупает одно понятное улучшение.

К концу урока враги будут давать монеты, а игрок сможет купить усиление урона стрел.

---

## Зачем нужен `GameManager`?

Не все данные принадлежат одному врагу или одной стреле.

Например:

- сколько монет у игрока;
- сколько стоит улучшение;
- что показывать в UI.

Эти данные удобно хранить в отдельном объекте `GameManager`.

## Пояснение (роль GameManager)

`GameManager` хранит то, что относится ко всей партии, а не к одному объекту.

Монеты игрока — общие.
Они не принадлежат конкретной стреле или конкретному врагу.

Поэтому `GameManager` становится местом, где хранится общее состояние игры.

## Практика 1: Создайте `GameManager`

Сейчас добавим главный скрипт, который будет хранить деньги игрока.
После этой практики у игры появится место, где можно считать монеты.

### Шаг 1: Планирование

- `GameManager` должен хранить общее состояние игры.

- Чтобы враги могли выдавать награду, нужен метод начисления.
- Компьютер не умеет догадываться, где хранить деньги, — значит появятся поле `currency` и метод `AddCurrency`.

### Шаг 3: Добавьте монеты и метод начисления

`GameManager` должен помнить деньги и уметь прибавлять награду. Сам компьютер не догадается, что число монет нужно хранить в `currency`, а изменение делать через `AddCurrency`.

Поэтому добавляем начало кода с полем `currency` и методом `AddCurrency`:

```csharp
using UnityEngine;

public class GameManager : MonoBehaviour
{
    // Общее количество монет игрока
    public int currency;

    // Начисляет монеты за события в игре
    public void AddCurrency(int amount)
    {
        // Увеличиваем общий счёт
        currency += amount;
        Debug.Log("Монеты: " + currency);
    }
}
```

## Как `GameManager` начисляет монеты

> **Как это работает (по шагам):**
>
> 1. Другой объект вызывает `AddCurrency(int amount)` и передаёт сумму.
> 2. `currency += amount` прибавляет эту сумму к общим монетам игрока.
> 3. В первой версии результат выводится через `Debug.Log(...)`.
> 4. Позже этот же метод будет обновлять UI, но роль останется той же: менять общее состояние игры.

Урок про деньги легко превратить в бесконечный магазин. Поэтому сразу договоримся, чего сегодня не делаем:

## Практика 2: Награда за врага

Сейчас сделаем так, чтобы за победу над врагом давались монеты.
После этой практики игрок начнёт получать награду за хорошие выстрелы.

### Шаг 1: Планирование

- Враг должен сообщать, что он уничтожен и за него надо выдать награду.
- Для этого ему нужно знать, кому сообщить: это ссылка на `GameManager`.
- Ещё врагу нужно хранить, сколько монет он даёт.
- Компьютер не догадается сам, какой враг сколько стоит, — значит появятся поля `gameManager` и `reward`, а смерть вынесем в метод `Die`.

---

### Шаг 2: Добавьте врагу ссылку и награду

Откройте `EnemyUnit.cs`.
Враг должен отправить награду не в пустоту, а конкретному менеджеру. Компьютер не догадается, сколько монет даёт враг, поэтому явно добавляем ссылку `gameManager` и число `reward`.

Поэтому добавляем два поля:

```csharp
// Ссылка на общий менеджер игры
public GameManager gameManager;

// Сколько монет даёт этот враг
public int reward = 3;
```

---

### Шаг 3: Добавьте метод `Die()`

Смерть врага должна быть отдельным действием: сначала начислить награду, потом убрать объект. Компьютер не догадается, что эти команды связаны, поэтому собираем их в метод `Die()`.

```csharp
// Вызывается, когда здоровье врага закончилось
private void Die()
{
    // Если менеджер назначен, отправляем ему награду
    if (gameManager != null)
    {
        gameManager.AddCurrency(reward);
    }

    // Удаляем врага со сцены
    Destroy(gameObject);
}
```

---

### Шаг 4: Используйте `Die()` в `TakeDamage`

`TakeDamage` должен не просто удалить врага, а запустить весь сценарий смерти. Робот сам не догадается начислить награду перед удалением, поэтому вместо прямого `Destroy` вызываем `Die()`.

Поэтому в `TakeDamage` заменяем `Destroy(gameObject)` на:

```csharp
// Завершаем врага через отдельный метод смерти
Die();
```

> **Как это работает (по шагам):**

> 2. Если `!IsAlive()`, враг вызывает `Die()`.
> 3. `Die()` проверяет, назначен ли `gameManager`.
> 4. Если ссылка есть, `gameManager.AddCurrency(reward)` начисляет награду.
> 5. После этого `Destroy(gameObject)` удаляет врага.

### Если успеваете: эффект при уничтожении врага

Это необязательная часть. Основная механика урока уже работает — беритесь за эффект, только если всё остальное готово.

Игрок должен увидеть, что враг исчез не просто так. Значит врагу нужно хранить prefab эффекта, потому что робот сам не догадается, что именно создавать. Добавьте поле в `EnemyUnit.cs`, а в самое начало `Die()` — создание эффекта:

```csharp
// Prefab короткого эффекта смерти
public GameObject deathEffectPrefab;

// ... а внутрь Die(), самой первой строкой:
if (deathEffectPrefab != null)
{
    Instantiate(deathEffectPrefab, transform.position, Quaternion.identity);
}
```

`Quaternion.identity` уже знаком: он означает «создать без дополнительного поворота». Проверка `!= null` нужна, чтобы игра не ломалась, если prefab эффекта в поле не положили.

### 💡 Лайфхак: обратная связь нужна не только смерти врага

Такой приём можно применять не только к уничтожению врага.
Если у вас есть prefab эффекта, его можно создавать через `Instantiate(...)` в разных местах игры.

Хорошие места для обратной связи:

- урон по врагу;
- выстрел арбалета;
- покупка улучшения;
- победа;
- проигрыш;
- появление новой волны.

И это не обязательно должен быть только particle effect.
Внутрь prefab можно добавлять анимации, звуки, короткое дрожание камеры, вспышку UI или изменение цвета.
Главная идея: игрок должен сразу понять, что его действие или событие в игре сработало.

## Практика 3: Текст монет

Сейчас выведем монеты на экран через TextMeshPro.
После этой практики игрок будет сразу видеть, сколько денег у него есть.

---

### Шаг 1: Планирование

- Игрок должен видеть монеты не в Console, а на экране.
- Для этого `GameManager` должен знать, в какой UI-текст писать.
- При запуске и после начисления монет текст надо обновлять.
- Компьютер не догадается, какую надпись менять, — значит появятся `currencyText`, `Start()` и `UpdateCurrencyText()`.

---

### Шаг 2: Создайте UI-текст `CurrencyText`

1. В `Hierarchy` нажмите правой кнопкой мыши -> `UI` -> `Canvas`. Если `Canvas` в сцене уже есть, второй создавать не нужно.
2. Нажмите правой кнопкой **на `Canvas`** -> `UI` -> `Text - TextMeshPro`. Если Unity предложит `Import TMP Essentials`, нажмите эту кнопку один раз.
3. Переименуйте новый объект в `CurrencyText`.
4. В `Inspector` в компоненте `TextMeshPro - Text (UI)` в поле ввода напишите `Монеты: 0`.
5. Там же поставьте `Font Size` = `36`.
6. В компоненте `Rect Transform` нажмите на квадрат `Anchor Presets` (слева вверху) и выберите верхний левый вариант — надпись прижмётся к левому верхнему углу экрана.
7. Поставьте `Pos X` = `120`, `Pos Y` = `-40`, чтобы текст не прилипал к самому краю.

### Шаг 3: Подключите поле текста в коде

`GameManager` должен хранить не только число монет, но и ссылку на надпись. Сам компьютер не догадается, куда выводить `currency`, поэтому добавляем поле `currencyText`. А чтобы C# знал, откуда взять тип `TMP_Text`, вверху файла нужен `using TMPro;`.

```csharp
using TMPro;   // нужен для типа TMP_Text

// ... внутри класса GameManager, рядом с currency:

// Текст на экране, куда выводим монеты
public TMP_Text currencyText;
```

`currencyText` мы назначим в Inspector в конце урока: перетащим туда объект `CurrencyText`.

---

### Шаг 4: Покажите стартовое значение

В начале игры игрок тоже должен видеть правильные монеты. Компьютер не догадается обновить UI сам, поэтому в `Start()` явно вызываем `UpdateCurrencyText()`.

В `Start()` сразу обновляем надпись, чтобы игрок видел `Монеты: 0` с начала сцены.

```csharp
// Вызывается один раз при запуске
void Start()
{
    UpdateCurrencyText();
}
```

`Start()` уже знаком по прошлым модулям. Здесь он просто вызывает метод обновления UI.

---

### Шаг 5: Обновляйте текст после начисления

Когда число монет меняется, экран должен измениться вместе с ним. Компьютер не догадается синхронизировать число и UI, поэтому после начисления вызываем `UpdateCurrencyText()`.

Когда монеты меняются, вызываем `UpdateCurrencyText()`.
Так код и UI остаются синхронными.

```csharp
// Начисляет монеты за события в игре
public void AddCurrency(int amount)
{
    // Увеличиваем общий счёт
    currency += amount;
    UpdateCurrencyText();
}

// Обновляет надпись монет на экране
private void UpdateCurrencyText()
{
    currencyText.text = "Монеты: " + currency;
}
```

`Debug.Log` уже не нужен: результат должен видеть игрок, а не только разработчик в Console.

> **Как это работает (по шагам):**
>

> 2. `currencyText` хранит ссылку на UI-текст.
> 3. `Start()` вызывает `UpdateCurrencyText()`, чтобы показать стартовое значение.
> 4. После начисления монет `AddCurrency(...)` снова вызывает `UpdateCurrencyText()`.
> 5. `currencyText.text = "Монеты: " + currency` собирает строку для игрока.

## Мини-теория: получить скрипт у созданного объекта

`Instantiate` и `GetComponent<>` уже знакомы по прошлым модулям.
Здесь используем их вместе: арбалет создаёт стрелу, а потом берёт её скрипт `BoltProjectile`.

Урон хранится не в самом `GameObject`, а в компоненте стрелы.

Арбалет должен передать урон не пустому объекту, а скрипту стрелы. Значит после создания нужно явно найти компонент `BoltProjectile`, потому что Unity не выберет его за нас.

Поэтому берём компонент так:

```csharp
// Берём скрипт стрелы с созданного объекта
BoltProjectile bolt = boltObject.GetComponent<BoltProjectile>();
```

`GetComponent<BoltProjectile>()` берёт компонент стрелы на созданном объекте, чтобы арбалет мог записать туда текущий урон.

## Практика 4: Урон стрел как улучшение

Сейчас подготовим урон стрел к будущему улучшению.
После этой практики сила выстрела будет храниться в арбалете и передаваться стреле.

### Шаг 1: Планирование

- Улучшение должно усиливать новые стрелы.
- Для этого арбалету нужно хранить текущий урон выстрела.
- При создании стрелы арбалет должен передать ей это число.
- Компьютер не догадается, какой урон дать новой стреле, — значит появятся поле `boltDamage` и запись `bolt.damage = boltDamage`.

---

### Шаг 2: Добавьте урон в арбалет

Арбалет должен помнить силу своих будущих выстрелов. Компьютер не догадается, какое число считать уроном, поэтому добавляем поле `boltDamage`.

Сначала откройте `CrossbowShooter.cs`.
Поэтому добавляем поле:

```csharp
// Урон, который арбалет передаёт новой стреле
public int boltDamage = 1;
```

---

### Шаг 3: Передайте урон новой стреле

Созданная стрела должна получить урон от арбалета сразу после появления. Компьютер не догадается перенести это число сам, поэтому в `Shoot()` берём `BoltProjectile` и записываем ему `boltDamage`.

Поэтому меняем метод `Shoot()` так:

```csharp
// Создаёт стрелу и передаёт ей текущий урон
public void Shoot()
{
    // Создаём стрелу в точке выстрела с поворотом арбалета
    GameObject boltObject = Instantiate(boltPrefab, shootPoint.position, transform.rotation);

    // Получаем компонент стрелы, чтобы записать в него урон
    BoltProjectile bolt = boltObject.GetComponent<BoltProjectile>();

    if (bolt != null)
    {
        // Новая стрела получает текущий урон арбалета
        bolt.damage = boltDamage;
    }
}
```

Третий аргумент `transform.rotation` важен: стрела получает тот же поворот, что и арбалет, и летит туда, куда он смотрит.

## Как арбалет передаёт урон стреле

> **Как это работает (по шагам):**
>
> 1. `Instantiate(...)` создаёт новый объект стрелы и возвращает ссылку на него.
> 2. `boltObject.GetComponent<BoltProjectile>()` достаёт скрипт стрелы с созданного объекта.
> 3. Проверка `if (bolt != null)` защищает код от пустой ссылки.
> 4. `bolt.damage = boltDamage` записывает текущий урон арбалета в новую стрелу.
> 5. Поэтому уже созданные старые стрелы не меняются, а новые получают актуальный урон.

## Пояснение (почему урон задаёт арбалет)

Стрела живёт недолго: появилась, полетела, попала или исчезла.

А улучшение покупает игрок для арбалета.
Поэтому удобно хранить текущий урон в `CrossbowShooter`, а при создании новой стрелы передавать ей значение.

Поэтому строка `bolt.damage = boltDamage;` стоит именно в `Shoot()`: каждая новая стрела забирает у арбалета его текущий урон в момент рождения.

Уже летящие старые стрелы при этом не меняются — и это честно: улучшение действует со следующего выстрела.

## Теория 4: `\n` переносит текст на новую строку

Текст улучшения должен быть коротким, но понятным:

- что улучшает кнопка;
- какой сейчас уровень;
- сколько стоит покупка.

В C# внутри строки можно написать `\n`.
Это специальный символ переноса строки.
Например, для UI-счёта можно собрать текст так: `"Счёт: 5\nЗдоровье: 10"`.

Кнопка должна быстро объяснить игроку три вещи: что усиливаем, какой уровень сейчас и сколько нужно монет. Компьютер сам не разложит текст красиво, поэтому подскажем ему переносами `\n`.

```csharp
"Урон +1\nУровень: 1\nЦена: 10"
```

На экране это будет выглядеть как три строки:

```text
Урон +1
Уровень: 1
Цена: 10
```

## Практика 5: Покупка улучшения и кнопка

Сейчас добавим покупку, которая тратит монеты и усиливает стрелы, а потом повесим её на настоящую кнопку.
После этой практики игрок сможет прокачивать урон за заработанные деньги.

### Шаг 1: Планирование

- Покупка должна проверить монеты, списать цену и усилить арбалет.
- Для этого `GameManager` должен знать арбалет, цену, уровень улучшения и текст кнопки.
- Ещё нужны методы: один покупает улучшение, второй обновляет текст.
- Компьютер не догадается, что именно усиливать и что показывать, — значит появятся `crossbow`, `damageUpgradeCost`, `damageUpgradeLevel`, `upgradeText`, `BuyDamageUpgrade()` и `UpdateUpgradeText()`.

---

### Шаг 2: Добавьте поля для улучшения

`GameManager` должен уметь усилить арбалет и обновить кнопку. Значит ему нужно знать сам арбалет, цену, уровень и UI-текст, потому что компьютер сам не догадается, какие объекты связаны.

Откройте `GameManager.cs`.
Поэтому добавляем поля:

```csharp
// Ссылка на арбалет, который усиливаем
public CrossbowShooter crossbow;

// Цена и уровень одного улучшения урона
public int damageUpgradeCost = 10;
public int damageUpgradeLevel = 1;

// Текст кнопки улучшения
public TMP_Text upgradeText;
```

---

### Шаг 3: Добавьте метод покупки

Нажатие на кнопку должно стать понятной цепочкой: проверить монеты, списать цену, усилить урон и обновить экран. Компьютер не догадается собрать эти действия сам, поэтому пишем метод `BuyDamageUpgrade()` и обновление текста.

Поэтому метод покупки выглядит так:

```csharp
// Покупает улучшение урона стрел
public void BuyDamageUpgrade()
{
    // Если монет не хватает, покупка не проходит
    if (currency < damageUpgradeCost)
    {
        return;
    }
    // Списываем цену и усиливаем новые стрелы
    currency -= damageUpgradeCost;
    crossbow.boltDamage += 1;
    damageUpgradeLevel += 1;
    UpdateCurrencyText();
    UpdateUpgradeText();
}
```

Если монет не хватает, `return;` тихо завершает покупку. Это нормальное поведение для простой версии: игрок нажал кнопку, но ресурсов пока недостаточно.

---

### Шаг 4: Обновите текст кнопки

После покупки кнопка должна показать новый уровень и цену — иначе игрок не поймёт, что что-то произошло. Компьютер сам надпись не обновит, поэтому выносим её сборку в отдельный метод.

```csharp
// Обновляет текст на кнопке улучшения
private void UpdateUpgradeText()
{
    upgradeText.text = "Урон +1\nУровень: " + damageUpgradeLevel + "\nЦена: " + damageUpgradeCost;
}
```

И допишите вызов `UpdateUpgradeText();` в `Start()`, рядом с уже стоящим там `UpdateCurrencyText();`. Тогда кнопка покажет правильные уровень и цену с самого начала игры.

```check
  - contains: "BuyDamageUpgrade"
  - contains: "crossbow.boltDamage += 1"
  - contains: "UpdateUpgradeText"
```

> 2. Если монет мало, `return;` завершает метод без покупки.
> 3. `currency -= damageUpgradeCost` списывает цену.
> 4. `crossbow.boltDamage += 1` усиливает новые стрелы.
