# Модуль 5, Урок 4: `GameManager` — деньги, UI и одно улучшение

**Цель урока:** добавить общий управляющий объект, который хранит деньги игрока, обновляет UI и покупает одно понятное улучшение.

К концу урока враги будут давать монеты, игрок увидит их на экране и сможет купить усиление урона стрел.

---

## Зачем нужен `GameManager`?

Давай подумаем: где в нашей игре живут монеты игрока?

Здоровье живёт во враге. Урон живёт в стреле. А монеты не принадлежат ни одному врагу и ни одной стреле — они общие для всей партии.

Значит, монетам нужно общее место. Таким местом станет отдельный объект со скриптом `GameManager`.

## Пояснение (роль `GameManager`)

`GameManager` хранит то, что относится ко **всей партии**, а не к одному объекту.

Здоровье — личное дело врага, скорость — личное дело стрелы. А монеты общие, поэтому они и попадают в `GameManager`.

---

## Теория 1: монеты нужно не только считать, но и показывать

Число в переменной игрок не видит. Console видит только разработчик.

Значит, кроме поля с монетами нам нужна надпись на экране — UI-текст. В Unity для этого используем `TextMeshPro`, а в коде — тип `TMP_Text`.

`GameManager` будет менять число монет и сразу же обновлять эту надпись.

---

## Пояснение (текст как ссылка)

`TMP_Text` — это **ссылка на надпись** в UI, а не сами монеты.

Число монет по-прежнему хранится в `currency`. А `currencyText` нужен только для того, чтобы записать это число в текст на экране.

## Практика 1: Объект `GameManager` и надпись на экране

Сейчас поставим на сцену главный объект игры и надпись, в которой позже появятся монеты.
После этой практики в углу экрана будет видно `Монеты: 0`, а на сцене появится объект, готовый принять код.

### Шаг 1: Планирование

Что вообще должен уметь `GameManager` в этом уроке?

- хранить общее число монет — это поле `currency`;
- знать, в какую надпись писать — это поле `currencyText`;
- уметь начислять награду — это метод `AddCurrency`;
- уметь обновлять надпись — это метод `UpdateCurrencyText`.

Четыре понятных пункта — четыре куска кода. Сначала соберём объект и надпись на сцене, а потом допишем эти куски по одному.

## Практика 2: Монеты в коде

Сейчас научим менеджер считать монеты и записывать их в надпись.
После этой практики число на экране начнёт меняться по команде кода, а не стоять неподвижной картинкой.

### Шаг 1: Подключите библиотеку `TMPro`

Откройте `GameManager.cs`. Тип `TMP_Text` живёт в отдельной библиотеке, поэтому её надо подключить.

**В самую первую строку файла**, рядом с `using UnityEngine;`:

```csharp
using TMPro;   // нужен для типа TMP_Text
```

---

### Шаг 2: Добавьте поля `currency` и `currencyText`

Монеты не принадлежат ни одному врагу и ни одной стреле. Значит, им нужно общее место — поле в `GameManager`. А чтобы менеджер знал, **куда** писать это число, ему нужна вторая вещь: ссылка на надпись.

**Внутрь класса**, сразу под строкой с именем класса:

```csharp
// Общее количество монет игрока
public int currency;

// Надпись на экране, куда выводим монеты
public TMP_Text currencyText;
```

```check
rules:
  - filename: "GameManager.cs"
  - contains: "using TMPro"
  - contains: "public int currency"
  - contains: "public TMP_Text currencyText"
```

---

### Шаг 3: Покажите стартовое значение

В начале партии на экране уже должно быть честное число. Значит, обновить надпись нужно один раз при запуске сцены — это как раз работа для `Start()`.

Unity при создании скрипта положила туда пустой `Start()`. **Замените пустой `Start()` целиком** на этот:

```csharp
// Вызывается один раз при запуске сцены
void Start()
{
    UpdateCurrencyText();
}
```

Пока не спешите переключаться в Unity: она подчеркнёт `UpdateCurrencyText()` и скажет, что такого метода не существует. Всё в порядке — мы напишем его прямо в следующем шаге, и ошибка исчезнет сама.

---

### Шаг 4: Начисляйте монеты и обновляйте надпись

Награду будут присылать враги, поэтому нужен публичный метод, который принимает сумму. И сразу же после изменения числа экран должен догнать код — иначе игрок увидит старую цифру.

Добавьте в класс два метода:

```csharp
// Начисляет монеты за события в игре
public void AddCurrency(int amount)
{
    // Увеличиваем общий счёт
    currency += amount;
    UpdateCurrencyText();
}

// Обновляет надпись монет на экране
private void UpdateCurrencyText()
{
    currencyText.text = "Монеты: " + currency;
}
```

Сохраните файл — красное подчёркивание из прошлого шага пропадёт.

```check
rules:
  - filename: "GameManager.cs"
  - contains: "void Start()"
  - contains: "currency += amount"
  - contains: "UpdateCurrencyText"
  - contains: "currencyText.text"
```

---

### Шаг 5: Свяжите надпись и менеджер

Код готов, но поле `Currency Text` пока пустое — менеджер не знает, какую именно надпись менять.

1. Выделите объект `GameManager` в `Hierarchy`.
2. В `Inspector` найдите компонент `GameManager`.
3. Перетащите в поле **`Currency Text`** объект `CurrencyText` из `Hierarchy`.
4. Нажмите `Play`: в левом верхнем углу должно быть `Монеты: 0`.

```check

  - component_exists:

      type: "GameManager"
```

## Как монеты попадают на экран

> **Как это работает (по шагам):**
>
> 1. `currency` хранит число монет в коде.
> 2. `currencyText` хранит ссылку на UI-текст.
> 3. `Start()` вызывает `UpdateCurrencyText()` и показывает стартовое значение.
> 4. Любое начисление идёт через `AddCurrency(...)`, а он снова вызывает `UpdateCurrencyText()`.
> 5. Строка `currencyText.text = "Монеты: " + currency;` собирает то, что увидит игрок.

Важная идея: число меняется в одном месте, и надпись обновляется тоже в одном месте. Их невозможно рассинхронизировать.

---

## Если надпись не появилась

Проверьте по порядку:

- в сцене есть `Canvas`, а внутри него — `CurrencyText`;
- `CurrencyText` перетащен в поле `Currency Text` у `GameManager`;
- скрипт `GameManager` действительно висит на объекте `GameManager`;
- в Console нет `NullReferenceException`.

Если ошибка падает именно на строке `currencyText.text`, значит ссылка `currencyText` пустая.

Урок про деньги легко превратить в бесконечный магазин. Поэтому сразу договоримся, чего сегодня не делаем:

- разные типы врагов с разной наградой;

Сегодня цель одна: **монеты появляются, видны на экране и тратятся на одно понятное улучшение**. Если этот круг работает — урок удался.

## Практика 3: Награда за врага

Сейчас сделаем так, чтобы за победу над врагом давались монеты.
После этой практики игрок начнёт получать деньги за хорошие выстрелы.

### Шаг 1: Планирование

Что нужно знать врагу, чтобы выдать награду?

- **кому** её отдать — ссылка `gameManager`;
- **сколько** отдать — число `reward`;
- **когда** отдать — в момент собственной смерти.

Значит, будут два поля и отдельный метод `Die()`.

---

### Шаг 2: Добавьте врагу ссылку и награду

Награда должна улететь не в пустоту, а конкретному менеджеру. И размер награды у каждого врага может быть свой — значит, это тоже поле, которое видно в Inspector.

Откройте `EnemyUnit.cs` и добавьте два поля рядом с остальными:

```csharp
// Ссылка на общий менеджер игры
public GameManager gameManager;

// Сколько монет даёт этот враг
public int reward = 3;
```

---

### Шаг 3: Добавьте метод `Die()`

Смерть врага — это уже не одно действие, а маленький сценарий: сначала выдать награду, потом убрать объект со сцены. Такой сценарий удобно держать в одном месте, чтобы не повторять его в разных частях кода.

```csharp
// Вызывается, когда здоровье врага закончилось
private void Die()
{
    // Если менеджер назначен, отправляем ему награду
    if (gameManager != null)
    {
        gameManager.AddCurrency(reward);
    }

    // Удаляем врага со сцены
    Destroy(gameObject);
}
```

Проверка `!= null` спасает от падения игры, если ссылку в Inspector забыли поставить.

---

### Шаг 4: Используйте `Die()` в `TakeDamage`

Сейчас в `TakeDamage` враг просто исчезает. Но исчезнуть — это половина сценария смерти, награда при этом теряется.

В `EnemyUnit.cs` строка `Destroy(gameObject);` встречается **дважды**: один раз в `TakeDamage`, второй — в `OnTriggerEnter2D`. Менять нужно только первую. Во второй `Destroy` остаётся как был: враг, дошедший до базы, погибает без награды — он ведь не был убит.

Найдите метод `TakeDamage` и приведите его к такому виду:

```csharp
// Получает урон от стрелы
public void TakeDamage(int damage)
{
    currentHealth -= damage;
    if (!IsAlive())
    {
        Die();
    }
}
```

> **Как это работает (по шагам):**
>
> 1. `TakeDamage(int damage)` уменьшает здоровье врага.
> 2. Если `!IsAlive()`, враг вызывает `Die()`.
> 3. `Die()` проверяет, назначен ли `gameManager`.
> 4. Если ссылка есть, `gameManager.AddCurrency(reward)` начисляет награду.
> 5. И только после этого `Destroy(gameObject)` удаляет врага.

```check

  - contains: "public GameManager gameManager"
  - contains: "public int reward"
  - contains: "private void Die()"
  - contains: "if (gameManager != null)"
  - contains: "gameManager.AddCurrency(reward)"
  - contains: "Die();"
```

## Пояснение (пустая ссылка)

Если поле `Game Manager` у врага пустое, `if (gameManager != null)` просто не срабатывает: врагу некому отдать награду, и он молча исчезает.

Это не ошибка в `AddCurrency` и не проблема с монетами. Это обычная незаполненная ссылка в Inspector — самая частая причина «код правильный, а не работает».

---

### Если успеваете: эффект при уничтожении врага

Это необязательная часть. Основная механика урока уже работает — беритесь за эффект, только если всё остальное готово.

Добавьте в `EnemyUnit.cs` рядом с другими полями строку `public GameObject deathEffectPrefab;`, а в самое начало метода `Die()` — создание эффекта:

```csharp
// Показываем эффект там, где погиб враг
if (deathEffectPrefab != null)
{
    Instantiate(deathEffectPrefab, transform.position, Quaternion.identity);
}
```

`Quaternion.identity` уже знаком: «создать без дополнительного поворота». Проверка `!= null` нужна, чтобы игра не ломалась, если prefab эффекта в поле не положили.

Сам эффект соберите из `Effects` -> `Particle System`: в `Renderer` подставьте материал с текстурой `DeathParticle.png`, в `Main` снимите галочку `Looping` и поставьте `Stop Action` = `Destroy`, потом перетащите объект в папку `Prefabs`.

---

### 💡 Лайфхак: показывайте игроку, что действие сработало

`Instantiate(...)` с prefab-эффектом — универсальный приём обратной связи, не только для смерти врага.

Те же две строки годятся для выстрела, попадания или покупки улучшения.

А внутрь prefab можно положить не только частицы: анимацию, звук, вспышку.

Главное правило: игрок должен сразу видеть, что игра его услышала.

## Практика 4: Урон стрел как улучшение

Сейчас подготовим урон стрел к будущему улучшению.
После этой практики сила выстрела будет храниться в арбалете и передаваться каждой новой стреле.

### Шаг 1: Планирование

Давай подумаем, где должен жить урон.

Улучшение покупается один раз, а стрел за партию будут сотни. Значит, урон должен жить в арбалете, а не выставляться вручную у каждой стрелы.

Тогда арбалету нужно:

- поле `boltDamage` — текущая сила выстрела;
- строка в `Shoot()`, которая передаёт это число новой стреле.

---

### Шаг 2: Добавьте урон в арбалет и передайте его стреле

Откройте `CrossbowShooter.cs`. Сначала само число: игрок будет его прокачивать, поэтому оно должно быть видно в Inspector — делаем поле `public`.

```csharp
// Урон, который арбалет передаёт новой стреле
public int boltDamage = 1;
```

Теперь это число надо донести до стрелы. `Instantiate(...)` возвращает `GameObject` — просто объект сцены. А число урона лежит не в объекте, а в его компоненте `BoltProjectile`.

Значит, после создания стрелы нужно взять у неё нужный скрипт через `GetComponent<BoltProjectile>()` и уже ему записать урон.

**Замените метод `Shoot()` целиком** на этот:

```csharp
// Создаёт стрелу и передаёт ей текущий урон
public void Shoot()
{
    // Создаём стрелу в точке выстрела с поворотом арбалета
    GameObject boltObject = Instantiate(boltPrefab, shootPoint.position, transform.rotation);

    // Берём скрипт стрелы с созданного объекта
    BoltProjectile bolt = boltObject.GetComponent<BoltProjectile>();

    if (bolt != null)
    {
        // Новая стрела получает текущий урон арбалета
        bolt.damage = boltDamage;
    }
}
```

---

### Шаг 3: Убедитесь, что стрельба цела

Мы только что переписали `Shoot()` целиком — самая рискованная правка урока. Проверим её сразу.

1. Сохраните файл и вернитесь в Unity.
2. Нажмите **Play** и постреляйте по врагу.
3. В `Console` не должно быть красного, стрелы летят и убивают ровно как раньше.

Снаружи ничего не изменилось — и это правильный результат. Изменилось внутри: теперь урон приходит стреле от арбалета. Именно это число мы и научимся покупать.

## Как арбалет передаёт урон стреле

> **Как это работает (по шагам):**
>
> 1. `Instantiate(...)` создаёт объект стрелы и возвращает ссылку на него.
> 2. `boltObject.GetComponent<BoltProjectile>()` достаёт с этого объекта скрипт стрелы.
> 3. Проверка `if (bolt != null)` защищает от пустой ссылки, если у prefab забыли скрипт.
> 4. `bolt.damage = boltDamage` записывает текущий урон арбалета в новую стрелу.

```check
rules:
  - filename: "CrossbowShooter.cs"
  - contains: "public int boltDamage"
  - contains: "boltObject.GetComponent<BoltProjectile>()"
  - contains: "if (bolt != null)"
  - contains: "bolt.damage = boltDamage"
```

---

## Пояснение (почему урон задаёт арбалет)

Стрела живёт недолго: появилась, полетела, попала или исчезла. Хранить в ней прокачку бессмысленно — она улетит вместе со стрелой.

А арбалет стоит на сцене всю партию. Поэтому строка `bolt.damage = boltDamage;` стоит именно в `Shoot()`: каждая новая стрела забирает у арбалета его силу в момент рождения.

## Теория 4: `\n` переносит текст на новую строку

Что нужно знать игроку, глядя на кнопку? Три вещи: что улучшаем, какой сейчас уровень и сколько это стоит. В одну строчку это не влезет.

В C# внутри строки можно написать `\n` — это специальный символ переноса строки. Unity сама не догадается, где закончить строку, а `\n` говорит об этом явно.

Строка `"Урон +1\nУровень: 1\nЦена: 10"` покажется на экране так:

```text
Урон +1
Уровень: 1
Цена: 10
```

  - text: Одну строку `Урон +1 Цена: 10`

## Пояснение (`\n` — команда, а не буквы)

Здесь легко попасть в реальную ловушку. `\n` — это команда для C#, а не два символа для игрока.

Попробуйте вписать `Урон +1\nЦена: 10` прямо в поле текста у объекта в Inspector — переноса не будет. На экране появятся сами символы: обратный слэш и буква `n`. Inspector — это не код, он понимает `\n` буквально.

Правило простое: **в Inspector строки переносят клавишей Enter, а `\n` пишут только в коде.**

Поэтому надпись на кнопке мы собираем не руками в Inspector, а в методе — там `\n` работает как надо.

## Практика 5: Покупка улучшения в коде

Сейчас напишем саму покупку: она проверит монеты, спишет цену и усилит стрелы.
После этой практики метод улучшения будет готов, а надпись для кнопки будет собираться в коде — саму кнопку соберём следующей практикой.

### Шаг 1: Планирование

Что нужно знать кнопке улучшения? Кого усиливать, сколько это стоит, какой сейчас уровень и куда написать новую цену. Отсюда четыре поля.

А делать она будет две вещи: покупать (`BuyDamageUpgrade()`) и обновлять свою надпись (`UpdateUpgradeText()`).

---

### Шаг 2: Добавьте поля для улучшения

Откройте `GameManager.cs` и добавьте четыре поля рядом с `currency`:

```csharp
// Арбалет, который мы усиливаем
public CrossbowShooter crossbow;

// Цена и уровень одного улучшения урона
public int damageUpgradeCost = 10;
public int damageUpgradeLevel = 1;

// Текст на кнопке улучшения
public TMP_Text upgradeText;
```

`using TMPro;` для `upgradeText` уже стоит в начале файла — добавлять второй раз не нужно.

---

### Шаг 3: Добавьте метод покупки

Нажатие на кнопку — это короткая цепочка: проверить монеты, списать цену, усилить арбалет, обновить экран. Если денег мало, дальше идти нельзя, поэтому проверка стоит самой первой.

```csharp
// Покупает улучшение урона стрел
public void BuyDamageUpgrade()
{
    // Если монет не хватает, покупка не проходит
    if (currency < damageUpgradeCost)
    {
        return;
    }

    // Списываем цену и усиливаем новые стрелы
    currency -= damageUpgradeCost;
    crossbow.boltDamage += 1;
    damageUpgradeLevel += 1;
    UpdateCurrencyText();
    UpdateUpgradeText();
}
```

`return;` здесь просто тихо выходит из метода: игрок нажал кнопку, но денег пока нет.

> **Пока не переключайтесь в Unity:** она подчеркнёт `UpdateUpgradeText()` и скажет, что такого метода нет. Так и должно быть — напишем его следующим шагом.

---

### Шаг 4: Соберите текст кнопки

После покупки цифры на кнопке должны измениться — иначе игрок не поймёт, что вообще что-то произошло. Сборку надписи выносим в отдельный метод, чтобы вызывать её из двух мест.

```csharp
// Обновляет текст на кнопке улучшения
private void UpdateUpgradeText()
{
    upgradeText.text = "Урон +1\nУровень: " + damageUpgradeLevel + "\nЦена: " + damageUpgradeCost;
}
```

---

### Шаг 5: Обновите `Start()`

Второе место, где нужна эта надпись, — старт игры: цифры на кнопке должны быть честными ещё до первой покупки.

**Замените `Start()` целиком** на этот вариант:

```csharp
void Start()
{
    UpdateCurrencyText();
    UpdateUpgradeText();
}
```

> **Пока не нажимайте Play.** Поля `Upgrade Text` и `Crossbow` в Inspector ещё пустые — кнопки-то нет. `Start()` попробует написать текст в пустоту, и игра упадёт с `NullReferenceException`. Сначала сделаем кнопку и перетащим ссылки — это следующая практика.

```check
rules:
  - filename: "GameManager.cs"
  - contains: "public CrossbowShooter crossbow"
  - contains: "public TMP_Text upgradeText"
  - contains: "BuyDamageUpgrade"
  - contains: "crossbow.boltDamage += 1"
  - contains: "upgradeText.text"
```

---

## Как работает покупка улучшения

> **Как это работает (по шагам):**
>
> 1. `if (currency < damageUpgradeCost)` проверяет, хватает ли монет.
> 2. Если монет мало, `return;` завершает метод без покупки.
> 3. `currency -= damageUpgradeCost` списывает цену.
> 4. `crossbow.boltDamage += 1` усиливает новые стрелы.
> 5. `damageUpgradeLevel += 1` повышает уровень для надписи.
> 6. `UpdateCurrencyText()` и `UpdateUpgradeText()` обновляют обе надписи на экране.

```check
rules:
  - filename: "GameManager.cs"
  - contains: "if (currency < damageUpgradeCost)"
  - contains: "currency -= damageUpgradeCost"
  - contains: "damageUpgradeLevel += 1"
```

## Пояснение (что именно делает покупка)

Покупка делает ровно четыре вещи: списывает монеты, поднимает `boltDamage` у арбалета, поднимает уровень и обновляет обе надписи. Больше ничего.

Уже летящие по сцене стрелы при этом не меняются: каждая забрала себе урон в момент рождения. Улучшение действует со **следующего** выстрела — и это честно.

---

## Почему цена улучшения не растёт

А вот цена не меняется никогда. `damageUpgradeCost` как был `10`, так и останется `10` на десятой покупке — в коде её никто не трогает.

Это самый простой вариант и самый скучный: через пару волн монеты копятся быстрее, чем тратятся, и выбор «копить или потратить» исчезает.

Запомните это место. Если захотите дорабатывать игру своими руками — начинайте отсюда.
