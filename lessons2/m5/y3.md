# Модуль 5, Урок 3: Методы с ответом — `return`, база и проигрыш

**Цель урока:** научиться писать методы, которые возвращают ответ, и применить их в игре: можно ли стрелять, жив ли враг, разрушена ли база.

К концу урока у базы будет здоровье, а враг сможет нанести ей урон, если дойдёт до неё.

---

## Враг проходит сквозь стену — и ничего не происходит

Запустите игру и посмотрите на каменную стену перед замком. Враг доезжает до неё, спокойно проходит насквозь и уезжает за экран. Стена — просто картинка.

А значит, проиграть в нашей игре пока невозможно. Игра, в которой нельзя проиграть, — это не игра, а заставка: смотреть можно, напрягаться незачем.

Сегодня у базы появится прочность. Но чтобы она умела сказать «меня пробили», методам придётся научиться новому — **отвечать**.

---

## Зачем метод должен отвечать?

До сих пор наши методы что-то **делали**: двигали врага, поворачивали арбалет, создавали стрелу.

Но игре постоянно нужно другое — короткий ответ на вопрос:

- можно ли стрелять?
- жив ли враг?
- разрушена ли база?

У таких вопросов всего два ответа: да или нет. Тип `bool` уже знаком по прошлым модулям. Сегодня он впервые станет **типом ответа целого метода**.

## Пояснение (`bool` как ответ)

Метод с типом `bool` возвращает ровно два варианта: `true` или `false`. А `if` как раз и ждёт `true` или `false` — поэтому вызов такого метода можно поставить прямо в условие.

Именно поэтому имена вроде `IsAlive()`, `CanShoot()` и `HasLost()` читаются почти как обычные вопросы.

---

## Теория 1: `return` возвращает ответ

Слово `return` означает: «верни результат и закончи метод».

Давай подумаем: враг должен уметь ответить, жив он или нет. Значит, внутри него должна появиться строка, которая превращает здоровье в ответ да/нет:

```csharp
return currentHealth > 0;
```

Сначала C# считает условие `currentHealth > 0`. Если здоровье больше нуля — наружу уйдёт `true`, если нет — `false`.

Метод на этом заканчивается: всё, что написано после `return`, уже не выполнится.

## Что значит «метод отвечает»

Новых команд сегодня почти нет. `Time.time`, `ScreenToWorldPoint` и `Space.World` мы разобрали в прошлых уроках, а формулу поворота (`Atan2`, `Rad2Deg`, `Quaternion.Euler`) договорились взять готовой — так и берём.

Новая здесь ровно одна идея: **метод может не просто что-то делать, а возвращать ответ**.

И сразу закроем частую путаницу: `return` ничего не печатает. Он **отдаёт** ответ тому, кто вызвал метод. Показать ответ человеку — работа `Debug.Log`, а это совсем другое дело.

## Практика 1: Добавьте `IsAlive()` врагу

Сейчас добавим врагу простой вопрос: жив он или уже нет.
После этой практики другим скриптам будет легче понять, можно ли ещё атаковать этого врага.

### Шаг 1: Планирование

- Враг должен понимать, жив он или уже нет.
- Для этого ему нужно посмотреть на своё текущее здоровье.
- Компьютер не умеет догадываться, какое здоровье считать «живым» — границу задаём мы сами.
- Значит, добавим метод `IsAlive()`, который вернёт `true` или `false`.

---

### Шаг 2: Добавьте метод-вопрос

Строку `return currentHealth > 0;` из теории пора превратить в настоящий метод: у ответа должно быть имя, по которому его смогут позвать другие скрипты.

Откройте `EnemyUnit.cs` и добавьте метод внутрь класса `EnemyUnit`:

```csharp
// Отвечает, осталось ли у врага здоровье.
public bool IsAlive()
{
    return currentHealth > 0;
}
```

Теперь любой скрипт может спросить врага `IsAlive()` и получить короткий ответ вместо того, чтобы лезть в его здоровье самому.

---

### Шаг 3: Используйте метод в `TakeDamage`

После удара враг должен решить свою судьбу сам: остаться на сцене или исчезнуть. Порядок тут важен — сначала теряем здоровье, и только потом спрашиваем себя, живы ли мы ещё.

Метод `TakeDamage` у врага уже есть с прошлого урока. **Найдите метод `TakeDamage` и приведите его к такому виду** — второй метод с тем же именем в файле не уживётся:

```csharp
// Получает урон от стрелы.
public void TakeDamage(int damage)
{
    // Уменьшаем текущее здоровье.
    currentHealth -= damage;

    if (!IsAlive())
    {
        Destroy(gameObject);
    }
}
```

Знак `!` переворачивает ответ, поэтому `if (!IsAlive())` читается как «если враг не жив».

```check

  - contains: "public bool IsAlive()"

  - contains: "if (!IsAlive())"
```

---

## Как враг отвечает на вопрос "жив ли он"

> **Как это работает (по шагам):**
>
> 1. `IsAlive()` возвращает результат проверки `currentHealth > 0`.
> 2. После урона `TakeDamage(int damage)` уменьшает здоровье.
> 3. `if (!IsAlive())` читается как "если враг не жив".
> 4. В этом случае `Destroy(gameObject)` удаляет врага со сцены.

```check

  - filename: "EnemyUnit.cs"
  - contains: "currentHealth -= damage"
  - contains: "if (!IsAlive())"
  - contains: "Destroy(gameObject)"
```

### 💡 Лайфхак: называйте bool-методы как вопросы

`IsAlive()`, `CanShoot()`, `HasLost()` читаются как вопросы, на которые есть ответ «да» или «нет».

Такой код легче обсуждать и проверять: достаточно прочитать строку вслух — и сразу понятно, что она означает.

## Теория 2: `return;` как знакомый ранний выход

Ранний `return;` уже встречался раньше: он выходит из `void`-метода без результата.
В этом уроке он будет стоять рядом с `return`, который возвращает ответ.

Арбалет не должен продолжать выстрел, если кнопка даже не нажата. Значит, `Update()` нужно закончить сразу — не проверяя всё остальное:

```csharp
if (!Input.GetMouseButton(0))
{
    return;
}
```

Так арбалет мгновенно выходит из `Update()` и не тратит кадр впустую.

## Пояснение (ранний `return;`)

`return;` без значения означает просто: «дальше делать нечего, выходим из метода».

Это удобно: не нужно заворачивать весь код в один большой `if`. Все запреты стоят коротким списком в начале, а главный сценарий остаётся видно сверху вниз.

## Практика 2: Вынесите проверку выстрела в `CanShoot()`

Сейчас соберём правила выстрела в один понятный метод.
После этой практики арбалет будет стрелять только тогда, когда это действительно можно.

Честно предупредим: в игре после этой практики ничего не изменится. Зачем тогда `CanShoot()`? Затем, что через двадцать минут точно такой же метод-вопрос `HasLost()` будет решать судьбу всей партии. Сейчас мы тренируем приём на безопасном месте, где любая поломка видна сразу — арбалет либо стреляет, либо нет.

### Шаг 1: Планирование

Ничего нового арбалету дописывать не придётся — поля `boltPrefab`, `shootPoint`, `shootCooldown`, `nextShootTime` и методы `AimAtMouse()` и `Shoot()` у него уже есть с первого урока. Их мы не трогаем.

Меняем только две вещи:

- правило «пауза уже прошла?» вынесем в отдельный метод-вопрос `CanShoot()`;
- перепишем `Update()` так, чтобы он читался как список условий допуска к выстрелу.

---

### Шаг 2: Добавьте метод `CanShoot()`

Перед выстрелом арбалет должен спросить сам себя: «моя пауза уже закончилась?» Чтобы ответить, ему нужно сравнить текущее время с `nextShootTime` — а раз это вопрос с ответом да/нет, оформляем его методом `bool`.

Добавьте в `CrossbowShooter.cs`:

```csharp
// Отвечает, прошёл ли кулдаун выстрела.
public bool CanShoot()
{
    return Time.time >= nextShootTime;
}
```

`Time.time` растёт с начала сцены, поэтому его удобно сравнивать с временем следующего выстрела.

---

### Шаг 3: Обновите `Update()`

Каждый кадр арбалет проходит один и тот же маршрут: прицелиться, проверить кнопку, проверить паузу и только потом стрелять. Запишем этот маршрут явно, сверху вниз.

**Замените старый `Update()` целиком** на этот — второй метод с таким же именем в файле не уживётся:

```csharp
// Вызывается каждый кадр.
void Update()
{
    AimAtMouse();
    if (!Input.GetMouseButton(0))
    {
        return;
    }
    if (!CanShoot())
    {
        return;
    }
    Shoot();
    nextShootTime = Time.time + shootCooldown;
}
```

Два `return;` отсекают ситуации, когда стрелять нельзя. Метод `Shoot()` остаётся точно таким же, каким был в первом уроке — переписывать его не нужно.

Запустите Play — игра выглядит ровно так же, и это правильно. Мы не меняли поведение, мы сделали код читаемым. Это называется **рефакторинг**, и в настоящей разработке им занимаются постоянно.

```check
rules:
  - filename: "CrossbowShooter.cs"
  - contains: "public bool CanShoot()"
  - contains: "return Time.time >= nextShootTime"
  - contains: "if (!CanShoot())"
```

---

## Как читается новый `Update()` арбалета

> **Как это работает (по шагам):**
>
> 1. `AimAtMouse()` выполняется каждый кадр, чтобы арбалет смотрел на мышь.
> 2. Если кнопка мыши не нажата, `return;` сразу завершает `Update()`.
> 3. Если `CanShoot()` вернул `false`, второй `return;` тоже останавливает метод.
> 4. Только после двух проверок вызывается `Shoot()`.
> 5. `nextShootTime = Time.time + shootCooldown` назначает время следующего выстрела.

```check
rules:
  - filename: "CrossbowShooter.cs"
  - contains: "if (!Input.GetMouseButton(0))"
  - contains: "Shoot();"
  - contains: "nextShootTime = Time.time + shootCooldown"
```

---

### 💡 Лайфхак: `return;` делает код плоским

Если условие запрещает действие, можно сразу выйти из метода через `return;`.

Так не приходится вкладывать весь код внутрь большого `if`, а основной сценарий остаётся виден сверху вниз.

## Практика 3: Скрипт `DefensePoint`

Сейчас создадим базу, которую нужно защищать.
После этой практики у игры появится точка с запасом здоровья.

### Шаг 1: Планирование

- База должна хранить здоровье и понимать, разрушена она или нет.
- Когда враг доходит до базы, база должна получить урон.
- Значит, в `DefensePoint` появятся поле `health`, метод `TakeDamage()` и метод-вопрос `HasLost()`.

---

### Шаг 2: Дайте базе коллайдер

Объект `DefensePoint` мы поставили на сцену ещё в первом уроке, но он до сих пор просто картинка. Чтобы враг мог в него «врезаться», базе нужен коллайдер — иначе Unity никогда не заметит столкновение.

1. Выделите `DefensePoint` в `Hierarchy`.
2. В `Inspector` нажмите `Add Component`, введите `Box Collider 2D` и выберите его.
3. Поставьте у коллайдера галочку `Is Trigger`.

> **Проверьте размер сразу.** Спрайт стены стоит на месте с первого урока, поэтому коллайдер снял мерку правильно: он подогнался под границы спрайта, повернулся вместе с объектом и перекрывает по высоте от `-3.7` до `+3.7`. Если рамка коллайдера в `Scene` не совпала со стеной — правой кнопкой по `Box Collider 2D` -> `Reset`.

> **А `Rigidbody2D` базе нужен?** Нет. Для trigger-события достаточно, чтобы `Rigidbody2D` был **хотя бы у одного** из двух объектов. У врага он уже есть — этого хватит. База стоит неподвижно, ей физика не нужна.

### Шаг 3: Создайте скрипт базы

1. В папке `Scripts` нажмите правой кнопкой -> `Create` -> `C# Script`. Назовите файл `DefensePoint`.
2. Выделите объект `DefensePoint` в `Hierarchy`.
3. В `Inspector` нажмите `Add Component`, введите `DefensePoint` и выберите скрипт в списке.

Unity создаст заготовку с пустыми `Start()` и `Update()`. Базе они не нужны: она ничего не делает каждый кадр, а только отвечает на удары. Эти два пустых метода можно смело удалить — файл станет чище.

### Шаг 4: Добавьте здоровье

База должна уметь терять прочность. Значит, ей нужно число, которое можно уменьшать — заводим поле `health`.

```csharp
public int health = 10;
```

Начальное значение `10` можно будет изменить в Inspector.

---

### Шаг 5: Добавьте получение урона

Когда враг ударил базу, база делает два дела подряд: уменьшает здоровье и сразу проверяет, не проиграли ли мы. Второй шаг — это как раз вопрос, поэтому в коде появится вызов `HasLost()`.

```csharp
// Получает урон от врага.
public void TakeDamage(int damage)
{
    // Уменьшаем здоровье базы.
    health -= damage;

    if (HasLost())
    {
        Debug.Log("База разрушена!");
    }
}
```

Пока не переключайтесь в Unity: она скажет, что метода `HasLost()` не существует. Это нормально — допишем его следующим шагом, и ошибка исчезнет сама.

---

### Шаг 6: Добавьте проверку проигрыша

База должна понимать, что её пробили. Значит, ей нужен метод, который отвечает одним словом: разрушена или нет. Границу выбираем мы — здоровье `0` или меньше.

```csharp
// Отвечает, разрушена ли база.
public bool HasLost()
{
    return health <= 0;
}
```

## Практика 4: Враг наносит урон базе

Сейчас научим врага добираться до базы и бить её.
После этой практики защита станет настоящей задачей, потому что база сможет терять здоровье.

`BoltProjectile` из прошлого урока не переписываем: он уже вызывает `EnemyUnit.TakeDamage(damage)`.

### Шаг 1: Планирование

- Враг должен понять, что дошёл именно до базы.
- Для этого при столкновении нужно проверить, есть ли на другом объекте `DefensePoint`.
- Компьютер не умеет сам отличать базу от любого другого коллайдера — правило пишем явно.
- Значит, добавим `OnTriggerEnter2D()`, найдём `DefensePoint`, нанесём урон и удалим врага.

---

### Шаг 2: Добавьте столкновение с базой

Враг должен бить только базу, а не любой предмет на пути. Надёжный способ узнать базу — спросить у объекта его компонент `DefensePoint`: если он есть, перед нами точно база.

Откройте `EnemyUnit.cs` и добавьте метод внутрь класса `EnemyUnit`:

```csharp
// Срабатывает, когда враг пересёкся с trigger-коллайдером.
void OnTriggerEnter2D(Collider2D other)
{
    DefensePoint defensePoint = other.GetComponent<DefensePoint>();

    if (defensePoint == null)
    {
        return;
    }

    defensePoint.TakeDamage(1);
    Destroy(gameObject);
}
```

Если на объекте нет `DefensePoint`, враг сразу выходит из метода — знакомый ранний `return;`.

  - contains: "OnTriggerEnter2D"
  - contains: "GetComponent<DefensePoint>()"
  - contains: "defensePoint.TakeDamage(1)"

## Как враг бьёт базу

> **Как это работает (по шагам):**
>
> 1. `OnTriggerEnter2D(Collider2D other)` срабатывает, когда враг пересёкся с другим 2D-коллайдером.
> 2. `other.GetComponent<DefensePoint>()` проверяет, не база ли перед ним.
> 3. Если `defensePoint == null`, враг столкнулся не с базой, поэтому делает `return;`.
> 4. Если база найдена, `defensePoint.TakeDamage(1)` наносит ей урон.
> 5. После удара `Destroy(gameObject)` удаляет врага.

## Пояснение (почему враг исчезает)

Мы делаем простую версию игры.
Если враг дошёл до базы:

1. база получает урон;
2. враг исчезает;
3. игрок понимает, что пропустил угрозу.

Это проще, чем заставлять врага стоять у базы и атаковать по таймеру.
Такую механику можно добавить позже, когда основа уже понятна.

## Если база не получает урон

Проверьте сцену:

- `DefensePoint` стоит на пути врага, и у него есть `Box Collider 2D` с галочкой `Is Trigger`;
- у `Enemy` есть `Circle Collider 2D` с галочкой `Is Trigger`;
- у `Enemy` есть `Rigidbody 2D`: `Body Type` = `Kinematic`, `Gravity Scale` = `0`;
- метод `OnTriggerEnter2D` находится именно в `EnemyUnit`.

Если объекты визуально пересекаются, но `Health` не меняется, значит Unity не видит trigger-событие.
