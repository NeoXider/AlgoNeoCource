# Модуль 5, Урок 3: Методы с ответом — `return`, база и проигрыш

**Цель урока:** научиться писать методы, которые возвращают ответ, и применить их в игре: можно ли стрелять, жив ли враг, разрушена ли база.

К концу урока у базы будет здоровье, а враг сможет нанести ей урон, если дойдёт до неё.

---

## Зачем метод должен отвечать?

Иногда метод не просто делает действие.
Он отвечает на вопрос:

- можно ли стрелять?
- жив ли враг?
- разрушена ли база?

`bool` уже знаком по прошлым модулям. Теперь используем его как тип ответа у метода.

Давай подумаем: враг должен отвечать, жив ли он. Значит, ему нужно сравнить своё здоровье с нулём; робот сам не догадается, поэтому делаем метод `IsAlive()` с ответом `bool`.

```csharp
// Отвечает, осталось ли у врага здоровье.
public bool IsAlive()
{
    return currentHealth > 0;
}
```

## Пояснение (`bool` как ответ)

Метод с типом `bool` возвращает только два варианта: `true` или `false`.

Поэтому имена вроде `IsAlive()`, `CanShoot()` и `HasLost()` читаются почти как обычные вопросы.

---

## Теория 1: `return` возвращает ответ

Слово `return` означает: "верни результат и закончи метод".

Например:

Что роботу нужно вернуть на вопрос «жив?» Не слова, а готовый ответ `true` или `false`, поэтому явно возвращаем проверку здоровья.

```csharp
return currentHealth > 0;
```

Здесь C# сначала проверяет условие.
Если здоровье больше нуля, вернётся `true`.
Если нет — `false`.

## Практика 1: Добавьте `IsAlive()` врагу

Сейчас добавим врагу простой вопрос: жив он или уже нет.
После этой практики другим скриптам будет легче понять, можно ли ещё атаковать этого врага.

### Шаг 1: Планирование

- Враг должен понимать, жив он или уже нет.
- Для этого ему нужно посмотреть на своё текущее здоровье.
- Компьютер не умеет догадываться, какой ответ считать "жив".
- Значит, добавим метод `IsAlive()`, который вернёт `true` или `false`.

Откройте `EnemyUnit.cs`.
Добавьте метод внутрь класса `EnemyUnit`:

Давай подумаем: другие скрипты должны уметь быстро спросить врага, жив ли он. Компьютер сам не выберет правило «жив», поэтому явно пишем метод-вопрос `IsAlive()`, который смотрит на `currentHealth`.

### Шаг 3: Используйте метод в `TakeDamage`

После удара враг должен решить сам: остаться на сцене или исчезнуть. Значит сначала он теряет здоровье, а потом спрашивает себя `IsAlive()` — компьютер не догадается, в какой момент удалять объект.

```csharp
// Получает урон от стрелы.
public void TakeDamage(int damage)
{
    // Уменьшаем текущее здоровье.
    currentHealth -= damage;

    if (!IsAlive())
    {
        Destroy(gameObject);
    }
}
```

`!IsAlive()` читается как "если враг не жив".

> 3. `if (!IsAlive())` читается как "если враг не жив".

## Теория 2: `return;` как знакомый ранний выход

Ранний `return;` уже встречался раньше: он выходит из `void`-метода без результата.
В этом уроке он будет стоять рядом с `return`, который возвращает ответ.

Арбалет не должен продолжать выстрел, если кнопка не нажата. Робот сам не остановится, поэтому заранее ставим короткий выход `return;`.

```csharp
if (!Input.GetMouseButton(0))
{
    return;
}
```

Так арбалет сразу выходит из `Update()`, если кнопка мыши не нажата.

## Пояснение (ранний `return;`)

`return;` без значения означает просто: «дальше делать нечего, выходим из метода».

Это удобно: не нужно заворачивать весь код в один большой `if`. Все запреты стоят коротким списком в начале, а главный сценарий остаётся видно сверху вниз.

## Практика 2: Вынесите проверку выстрела в `CanShoot()`

Сейчас соберём правила выстрела в один понятный метод.
После этой практики арбалет будет стрелять только тогда, когда это действительно можно.

### Шаг 1: Планирование

Ничего нового арбалету дописывать не придётся — поля `boltPrefab`, `shootPoint`, `shootCooldown`, `nextShootTime` и методы `AimAtMouse()` и `Shoot()` у него уже есть с первого урока. Их мы не трогаем.

Меняем только две вещи:

- правило «пауза уже прошла?» вынесем в отдельный метод-вопрос `CanShoot()`;
- перепишем `Update()` так, чтобы он читался как список условий допуска к выстрелу.

---

### Шаг 2: Добавьте метод `CanShoot()`

Перед выстрелом арбалет должен спросить сам себя: «моя пауза уже закончилась?» Для ответа ему нужно сравнить текущее время с `nextShootTime` — поэтому добавляем в `CrossbowShooter.cs` метод-вопрос `CanShoot()`.

```csharp
// Отвечает, прошёл ли кулдаун выстрела.
public bool CanShoot()
{
    return Time.time >= nextShootTime;
}
```

`Time.time` растёт с начала сцены, поэтому его удобно сравнивать с временем следующего выстрела.

---

### Шаг 3: Обновите `Update()`

Каждый кадр арбалет должен пройти один и тот же маршрут: прицелиться, проверить кнопку, проверить паузу и только потом стрелять. Компьютер сам такой порядок не выстроит — записываем его в `Update()` явно.

```csharp
// Вызывается каждый кадр.
void Update()
{
    AimAtMouse();
    if (!Input.GetMouseButton(0))
    {
        return;
    }
    if (!CanShoot())
    {
        return;
    }
    Shoot();
    nextShootTime = Time.time + shootCooldown;
}
```

Два `return;` отсекают ситуации, когда стрелять нельзя. Метод `Shoot()` остаётся точно таким же, каким был в первом уроке — переписывать его не нужно.


## Как читается новый `Update()` арбалета

> **Как это работает (по шагам):**
>
> 1. `AimAtMouse()` выполняется каждый кадр, чтобы арбалет смотрел на мышь.
> 2. Если кнопка мыши не нажата, `return;` сразу завершает `Update()`.
> 3. Если `CanShoot()` вернул `false`, второй `return;` тоже останавливает метод.
> 4. Только после двух проверок вызывается `Shoot()`.
> 5. `nextShootTime = Time.time + shootCooldown` назначает время следующего выстрела.

```check

  - filename: "CrossbowShooter.cs"
  - contains: "if (!Input.GetMouseButton(0))"
  - contains: "Shoot();"
  - contains: "nextShootTime = Time.time + shootCooldown"
```

---

## Пояснение (ранний выход)

В `Update()` у арбалета теперь два ранних выхода:

- если мышь не нажата — ничего не делаем;
- если кулдаун ещё не прошёл — тоже ничего не делаем.

Только после этих проверок вызывается `Shoot()`.
Так код читается сверху вниз как список условий допуска к выстрелу.

## Практика 3: Скрипт `DefensePoint`

Сейчас создадим базу, которую нужно защищать.
После этой практики у игры появится точка с запасом здоровья.

### Шаг 1: Планирование

- База должна хранить здоровье и понимать, разрушена она или нет.
- Когда враг доходит до базы, база должна получить урон.
- Компьютер не умеет сам решать, где хранить здоровье и когда считать проигрыш.
- Значит, в `DefensePoint` появятся поле `health`, метод `TakeDamage()` и метод-вопрос `HasLost()`.

### Шаг 2: Дайте базе коллайдер

Объект `DefensePoint` мы поставили на сцену ещё в первом уроке, но он до сих пор просто картинка. Чтобы враг мог в него «врезаться», базе нужен коллайдер — иначе Unity никогда не заметит столкновение.

### Шаг 4: Добавьте здоровье

База должна уметь терять прочность. Значит, ей нужно где-то хранить число здоровья; робот сам такое место не создаст, поэтому добавляем поле `health`.

```csharp
public int health = 10;
```

Начальное значение `10` можно будет изменить в Inspector.

### Шаг 5: Добавьте получение урона

Когда враг ударил базу, база должна сама уменьшить здоровье и понять, не проиграли ли мы. Компьютер не догадается, что делать с числом урона, — поэтому метод `TakeDamage()` меняет `health` и сразу спрашивает `HasLost()`.

```csharp
// Получает урон от врага.
public void TakeDamage(int damage)
{
    // Уменьшаем здоровье базы.
    health -= damage;

    if (HasLost())
    {
        Debug.Log("База разрушена!");
    }
}
```

`Debug.Log` уже знаком: здесь он сообщает о проигрыше в Console.

---

### Шаг 6: Добавьте проверку проигрыша

База должна отвечать на вопрос «игра уже проиграна?» Значит, ей нужно сравнить своё здоровье с нулём; компьютер сам границу проигрыша не выберет, поэтому явно пишем метод `HasLost()`.

```csharp
// Отвечает, разрушена ли база.
public bool HasLost()
{
    return health <= 0;
}
```

Если `health` стал `0` или меньше, метод возвращает `true`.

Имя метода объясняет почти всё: `HasLost()` читается как вопрос «мы уже проиграли?».

## Практика 4: Враг наносит урон базе

Сейчас научим врага добираться до базы и бить её.
После этой практики защита станет настоящей задачей, потому что база сможет терять здоровье.

`BoltProjectile` из прошлого урока не переписываем: он уже вызывает `EnemyUnit.TakeDamage(damage)`.

### Шаг 1: Планирование

- Враг должен понять, что дошёл именно до базы.
- Для этого при столкновении нужно проверить, есть ли на другом объекте `DefensePoint`.
- Компьютер не умеет сам отличать базу от любого другого коллайдера.
- Значит, добавим `OnTriggerEnter2D()`, найдём `DefensePoint`, нанесём урон и удалим врага.

---

### Шаг 2: Добавьте столкновение с базой

Откройте `EnemyUnit.cs`.
Добавьте метод внутрь класса `EnemyUnit`:

Враг должен бить только базу, а не любой предмет на пути. Значит, при столкновении он ищет компонент `DefensePoint` — робот сам базу по названию не узнает.

```csharp
// Срабатывает, когда враг пересёкся с trigger-коллайдером.
void OnTriggerEnter2D(Collider2D other)
{
    DefensePoint defensePoint = other.GetComponent<DefensePoint>();

    if (defensePoint == null)
    {
        return;
    }

    defensePoint.TakeDamage(1);
    Destroy(gameObject);
}
```

Если на объекте нет `DefensePoint`, враг сразу выходит из метода.

## Как враг бьёт базу

> **Как это работает (по шагам):**
>
> 1. `OnTriggerEnter2D(Collider2D other)` срабатывает, когда враг пересёкся с другим 2D-коллайдером.
> 2. `other.GetComponent<DefensePoint>()` проверяет, не база ли перед ним.
> 3. Если `defensePoint == null`, враг столкнулся не с базой, поэтому делает `return;`.
> 4. Если база найдена, `defensePoint.TakeDamage(1)` наносит ей урон.
> 5. После удара `Destroy(gameObject)` удаляет врага.

## Пояснение (почему враг исчезает)

Мы делаем простую версию игры.
Если враг дошёл до базы:

1. база получает урон;
2. враг исчезает;
3. игрок понимает, что пропустил угрозу.

Это проще, чем заставлять врага стоять у базы и атаковать по таймеру.
Такую механику можно добавить позже, когда основа уже понятна.

## Если база не получает урон

Проверьте сцену:

- `DefensePoint` стоит на пути врага;
- у `DefensePoint` есть `Box Collider 2D`;
- у `Enemy` есть `Circle Collider 2D` и `Rigidbody 2D`;
- хотя бы один коллайдер работает как trigger;
- метод `OnTriggerEnter2D` находится именно в `EnemyUnit`.

Если объекты визуально пересекаются, но сообщения нет, значит Unity не видит trigger-событие.

### 💡 Лайфхак: называйте bool-методы как вопросы

`IsAlive()`, `CanShoot()`, `HasLost()` читаются как вопросы.
Такой код легче обсуждать и проверять: ответ всегда `true` или `false`.

---

### 💡 Лайфхак: `return;` делает код плоским

Если условие запрещает действие, можно сразу выйти из метода через `return;`.

Так не приходится вкладывать весь код внутрь большого `if`, а основной сценарий остаётся виден сверху вниз.
