# Модуль 5, Урок 6: Полировка, проверка и билд

**Цель урока:** довести Tower Defence до понятного финального состояния: проверить основные сценарии, настроить баланс, улучшить читаемость и собрать билд.

Новой большой механики сегодня не добавляем.
Главная задача — убедиться, что игра понятна и работает от начала до конца.

---

## Почему финальный урок спокойнее?

В конце модуля у всех разный темп:

- кто-то уже всё собрал и готов улучшать внешний вид;
- кто-то ещё чинит ссылки в Inspector;
- кто-то не успел подключить кнопку или спавнер.

Поэтому сегодня нет большой новой системы.
На доделку и починку отводим только первую часть урока.
Дальше у всех общий план: проверка, внешний вид, баланс и билд.

---

## Что должно быть в готовой игре?

К финалу урока проект должен уметь:

- стрелять из арбалета;
- создавать стрелы;
- двигать врагов к базе;
- наносить урон врагам;
- наносить урон базе;
- начислять монеты;
- покупать улучшение урона;
- создавать врагов через спавнер и волны;
- показывать счёт уничтоженных врагов;
- показывать экран проигрыша и кнопку перезапуска.

Теперь нужно проверить, что всё это работает вместе.

## Карта готовой игры

В финальной версии каждый объект держит свою роль:

| Объект | Скрипт | За что отвечает |
| ------ | ------ | --------------- |
| `Crossbow` | `CrossbowShooter` | создаёт стрелы и хранит текущий урон |
| `Bolt` | `BoltProjectile` | летит, наносит урон и исчезает |
| `Enemy` | `EnemyUnit` | идёт к базе, хранит HP и даёт награду |
| `DefensePoint` | `DefensePoint` | хранит здоровье базы и проверяет проигрыш |
| `GameManager` | `GameManager` | хранит монеты, счёт, UI, покупку улучшения и экран проигрыша |
| `EnemySpawner` | `EnemySpawner` | создаёт врагов и управляет волнами |

Это и есть ООП в нашей игре: не один огромный скрипт, а команда объектов с понятными обязанностями.

## Мини-теория: UI-состояние, пауза и перезапуск

Знакомое по прошлым модулям: `SetActive(false)` выключает объект на сцене, а `SetActive(true)` включает его обратно.

Для `GameOverPanel` это удобно: в начале игры панель скрыта, а при проигрыше появляется.

`Time.timeScale` управляет скоростью времени в игре.
`1f` — нормальная скорость, `0f` — пауза.

Для перезапуска используем уже знакомый `SceneManager.LoadScene(...)`.

## Практика 3: Добавьте счёт, Game Over и Restart

Сейчас добавим финальные элементы, которые показывают результат партии.

### Шаг 1: Планирование

`GameManager` должен показать игроку итог партии и дать начать заново.

Перед стартом спросим себя: что должен увидеть игрок в первую секунду?

### Шаг 4: Считайте уничтоженных врагов

Когда враг исчез, игрок ждёт не только монеты, но и плюс к счёту.
Компьютер сам не свяжет эти две награды, поэтому в `AddCurrency()` сразу увеличиваем счёт и обновляем текст.

```csharp
// Вызывается, когда враг уничтожен
public void AddCurrency(int amount)
{
    currency += amount;

    // Один вызов AddCurrency соответствует одному уничтоженному врагу
    enemiesKilled += 1;

    UpdateCurrencyText();
    UpdateScoreText();
}
```

Теперь при уничтожении врага меняются и монеты, и счёт.

### Шаг 5: Соберите текст счёта и принимайте здоровье базы

Нужны два коротких метода. Первый отвечает игроку на вопрос «какой сейчас счёт и сколько здоровья у базы?» — компьютер сам не превратит числа в аккуратную надпись. Второй нужен потому, что здоровье хранит база, а показывает его менеджер: двум объектам надо как-то договориться.

`\n` уже знаком по прошлому уроку — он переносит вторую часть надписи на новую строку.

```csharp
// Обновляет текст счёта и здоровья базы
private void UpdateScoreText()
{
    scoreText.text = "Счёт: " + enemiesKilled + "\nЗдоровье: " + playerHealth;
}

// Получает здоровье базы от DefensePoint
public void UpdateHealthText(int health)
{
    playerHealth = health;
    UpdateScoreText();
}
```

Владельцем здоровья остаётся база. `GameManager` только хранит копию числа для UI.

### Шаг 6: Добавьте проигрыш

Если база разрушена, игрок должен сразу понять: партия закончилась.
Компьютер сам не знает, что такое «проигрыш» в нашей игре, поэтому добавляем метод, который показывает панель и ставит игру на паузу.

```csharp
// Показывает финальный экран и ставит игру на паузу
public void GameOver()
{
    gameOverText.text = "Игра окончена\nСчёт: " + enemiesKilled;
    gameOverPanel.SetActive(true);

    // Останавливаем движение и спавн через общий масштаб времени
    Time.timeScale = 0f;
}
```

`Time.timeScale = 0f` останавливает игровое время.
Так игрок видит результат и может нажать кнопку перезапуска.

### Шаг 7: Добавьте перезапуск

Кнопка `Заново` должна вернуть игрока к чистому старту, как будто партия только началась.
Компьютер сам не выберет нужную сцену, поэтому метод явно берёт активную сцену и загружает её снова.

```csharp
// Возвращает время и загружает текущую сцену заново
public void RestartGame()
{
    Time.timeScale = 1f;
    SceneManager.LoadScene(SceneManager.GetActiveScene().name);
}
```

`SceneManager.GetActiveScene().name` берёт имя текущей сцены.
`LoadScene(...)` загружает её заново.

### Шаг 8: Свяжите базу с менеджером

База должна сообщать менеджеру своё здоровье, иначе UI будет молчать. Робот сам не поймёт, кому отправлять число, — поэтому добавляем в `DefensePoint.cs` ссылку на `GameManager` и сразу на старте отправляем ей своё здоровье.

```csharp
// Ссылка на менеджер, который обновляет UI и показывает проигрыш
public GameManager gameManager;

// Вызывается один раз при запуске базы
void Start()
{
    gameManager.UpdateHealthText(health);
}
```

Так `ScoreText` с самого начала показывает реальное здоровье базы, а не старую надпись из редактора.

### Шаг 9: Обновите `TakeDamage()` у базы

После удара здоровье стало меньше — значит и надпись должна измениться. А ещё база должна спросить себя: «я ещё держусь или игра закончилась?» Компьютер сам ни того, ни другого не сделает, поэтому дописываем `TakeDamage()`:

```csharp
// Получает урон от врага
public void TakeDamage(int damage)
{
    health -= damage;

    // Сообщаем UI новое здоровье базы
    gameManager.UpdateHealthText(health);

    if (HasLost())
    {
        gameManager.GameOver();
    }
}
```

`HasLost()` уже возвращает `true`, когда здоровье стало `0` или меньше.
При проигрыше база не показывает UI сама, а сообщает об этом `GameManager` — каждый объект остаётся при своей роли.

```check
rules:
  - filename: "DefensePoint.cs"
  - contains: "gameManager.UpdateHealthText(health)"
  - contains: "if (HasLost())"
  - contains: "gameManager.GameOver()"
```

### Шаг 11: Подключите ссылки в Inspector

## Теория 5: Перед билдом нужна проверка Console

Билд не исправляет ошибки автоматически.

Если в Console есть красная ошибка, она почти наверняка останется и в готовой игре.

Перед сборкой нужно:

- нажать Clear;
- запустить игру;
- пройти короткий сценарий;
- посмотреть, появились ли ошибки снова.

## Пояснение (Console перед билдом)

Console показывает техническое здоровье проекта.

Если в редакторе есть красные ошибки, в готовой игре они тоже могут сломать поведение.
Перед билдом лучше увидеть проблему, чем отдать игроку сломанную версию.
